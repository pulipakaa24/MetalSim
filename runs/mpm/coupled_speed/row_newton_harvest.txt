Metal: the ordered proxy-wrench harvest (`SolverImplicitMPM.coupling_harvest_proxy_wrenches`, used by `SolverCoupledProxy` and MetalSim's MPMCoupling) first compacts the collider nodes whose collider is a proxy body. The compaction is a stable integer scan (flag, exclusive scan, scatter), with no host reads, so it is capture-safe. Each body's 32 lanes then walk only the kept nodes of its world range. Before, every proxy body scanned every collider node of its world, which with one world means every active node. The per-node terms are unchanged. The lanes take kept nodes in turn, so the summation order differs (fixed: repeats exactly). Measured on the M4 Max with MetalSim's `multibody_sand.py` (1 world, about 73k particles): harvest 15.6-15.8 -> 1.5-1.7 ms per call; coupled step 47.7 -> 32.3 ms (4 bodies), 49.3 -> 34.2 ms (16), 80.7 -> 65.2 ms (64). Franka-Pour at 2,048 envs, whose world ranges were already short, is unchanged (1.80 s per policy step) and repeats bitwise. `NEWTON_METAL_HARVEST_COMPACT=0` restores the full scan, bitwise as before.
