## Q1. Newton ImplicitMPM: time integration, formulation, papers, grid, shapes, transfers, colliders, rigid coupling

### Takeaway
Newton's only MPM is `SolverImplicitMPM`: an implicit-in-time, nonsmooth (complementarity / yield-surface-as-constraint) granular-rheology MPM built on `warp.fem`, citing Daviet & Bertails-Descoubes 2016 (DOI 10.1145/2897824.2925877). It is not a Newton–Krylov hyperelastic solve and not MLS-MPM: by default velocity uses trilinear Q1 shape functions (not quadratic B-splines), stress is piecewise constant per cell (P0), the grid is a sparse NanoVDB `Nanogrid` (`wp.Volume`), transfers are APIC, and the coupled stress/contact problem is solved by colored Gauss-Seidel with per-node local yield-surface projections. Isaac Lab 3 exposes exactly this solver as its MPM backend, so "matching the Isaac/Newton reference" means matching this algorithm, not an MLS-MPM.

### Cited Findings
Identity, papers, scope
- Class docstring: "Implicit MPM solver for granular and elasto-plastic materials. Implements an implicit Material Point Method (MPM) algorithm roughly following [1], extended with a GPU-friendly rheology solver supporting pressure-dependent yield (Drucker-Prager), viscosity, dilatancy, and isotropic hardening/softening ... particularly well-suited for very stiff materials and the fully inelastic limit. It is less versatile than traditional explicit MPM but offers unconditional stability with respect to the time step." Reference [1] is `https://doi.org/10.1145/2897824.2925877` — [source: newton/_src/solvers/implicit_mpm/solver_implicit_mpm.py:757-796](https://doi.org/10.1145/2897824.2925877). That DOI is Daviet & Bertails-Descoubes, "A Semi-Implicit Material Point Method for the Continuum Simulation of Granular Materials", SIGGRAPH 2016 (ACM TOG 35(4)).
- Newton's solver list contains no explicit MPM; the only MPM solver directory is `implicit_mpm` (other solvers: featherstone, kamino, mujoco, semi_implicit, style3d, vbd, xpbd, coupled) — source: `upstream/newton/newton/_src/solvers/` listing. Newton's solver table labels it "Implicit" time integration and says it supports no joints — source: `upstream/newton/docs/solvers/index.rst:89-96, 207`.
- Isaac Lab 3 wraps it: `MPMSolverCfg(NewtonSolverCfg)` with `solver_type = "implicit_mpm"` and fields mirroring `SolverImplicitMPM.Config` (max_iterations 250, tolerance 1e-4, voxel_size 0.1, grid_type sparse, transfer_scheme apic, integration_scheme pic, air_drag 1.0) — source: `upstream/IsaacLab3/source/isaaclab_newton/isaaclab_newton/physics/mpm_manager_cfg.py`; manager at `.../physics/mpm_manager.py`; demos `upstream/IsaacLab3/scripts/demos/mpm/{newton_mpm_granular.py,newton_mpm_twoway_coupling.py,snowball_smash.py,teapot_fill.py}`.

Per-step pipeline (source: `solver_implicit_mpm.py:2875-2937`, `_step_impl`)
1. Bin particles into cells (`fem.PicQuadrature`; one quadrature point per particle for `integration_scheme="pic"`, or several overlapped cells per particle for `"gimp"`, `_particle_grid_locations_gimp` at :2760).
2. Rasterize colliders onto collider-basis nodes: SDF distance, normal, velocity, friction, adhesion, collider id (`rasterize_collider`).
3. "Unconstrained velocity": P2G of momentum and mass as `warp.fem` linear forms, then `v* = (Σ ρ φ (v_p + dt g) + APIC term) / (Σ ρ φ + air_drag·dt)` per node (`integrate_velocity`, `integrate_velocity_apic`, `integrate_mass`, `free_velocity` in `implicit_mpm_solver_kernels.py:119-207`). The APIC term is `ρ_p · (∇v)_p (x_node − x_p)` (affine velocity-gradient matrix, Jiang 2015 style); density 0 marks a kinematic particle with mass `INFINITY = 1e12`.
4. Collider rigidity (Delassus) operator `J · M⁻¹ Jᵀ` for finite-mass colliders (`build_rigidity_operator`, `rasterized_collisions.py:790`).
5. Elasticity system: compliance matrix (6×6 blocks per strain node) and RHS from each particle's elastic deformation gradient `F_e` (`compliance_form`, `strain_rhs`, `:507-576`).
6. Plasticity system: strain operator `B` (strain-node × velocity-node, from `fem.div(u)·τ·dt/V_cell`, `strain_delta_form`), yield parameters averaged to strain nodes, unilateral (incompressibility/critical-fraction) offset.
7. Warm-start, then `solve_rheology` (coupled stress projection + frictional contact), save warm-start.
8. G2P / advection: `v_p = v(x_p)` clamped to `particle_max_velocity`, `(∇v)_p = ∇v(x_p)`, `x_p += dt v_p`; update `F_e`, `J_p`, stress (`advect_particles`, `update_particle_strains`, `:332-425`).

The math being solved (source: `rheology_solver_kernels.py`, `solve_rheology.py:1889-1960`)
- Unknowns are grid velocities `u` and a symmetric stress `σ` per strain node (6-vector, `SymmetricTensorMapper` DB16), plus collider impulses per collider node. Docstring: "Solve coupled plasticity and collider contact ... Builds the Delassus operator diagonal blocks and rotates all local quantities into the decoupled eigenbasis (normal vs tangential) ... Runs either Gauss-Seidel (with coloring) or Jacobi iterations to solve the local stress projection problem per strain node ... Applies collider impulses and, when provided, a rigidity coupling step on collider velocities each iteration ... Iterates until the residual on the stress update falls below tolerance or max_iterations is reached."
- Yield surface (`YieldParamVec`, `shear_yield_stress`, :39-121): 6 params per node `[p_max·√(3/2), p_min·√(3/2), s_max, μ·p_max, dilatancy, viscosity/dt]`. Shear limit `|τ_T| ≤ s + μ·(r_N − p_min)` on the low-pressure branch, `s + μ·(p_max − r_N)` on the cap branch, flat in between, with `r_N ∈ [−p_min_tensile, p_max]` — i.e. a Drucker-Prager cone with cohesion `s` (yield_stress), tensile cutoff and a compressive cap (yield_pressure). A Modified Cam-Clay ellipse exists behind a development toggle `_USE_CAM_CLAY = False`.
- Local per-node solve `make_solve_flow_rule` (:587-651): given Delassus diagonal `D` (6-vector in eigenbasis) and RHS `b`, trial stress `r₀ = −b/D`; if `|r_T| ≤ ys` stick (shear rate zero, only normal clamp), else "sliding": scalar Newton (≤24 iterations, tol 1e-7) on `|b_T/(D+αI)| = ys` (anisotropic projection), optional dilatancy coupling `u_N = θ·ys'·|u_T|` (`solve_sliding_aniso`), viscosity as `D ← D/(1 + η/V·D)`. This is a non-associated flow rule (shear-rate along stress, volumetric part from dilatancy) — the Daviet-2016 "DP as constraint" approach generalised.
- Contact at collider nodes is a Coulomb cone with adhesion: `project_on_friction_cone`, `solve_coulomb_isotropic` (`contact_solver_kernels.py`), adhesion scaled `adhesion · dt · node_volume / voxel_size` (`rasterized_collisions.py:502`).
- Solver options: `"gs"`, `"gs-soa"`, `"gs-batched"` (colors merged into batches with Jacobi-style mass splitting; default for B2/B3), `"jacobi"`, and Krylov `"cg"/"cr"/"gmres"` which "only support solid materials without contacts"; sequences warm-start left-to-right. Defaults `max_iterations=250`, `tolerance=1e-4`, `solver="auto"` → `"gs"` for Q1 — source: `solver_implicit_mpm.py:823-838, 238-249`.
- Elasticity: Hencky (log) strain is on (`USE_HENCKY_STRAIN_MEASURE = True`): the compliance form applies isotropic Hooke `ε = ((1+ν)σ − ν tr(σ) I)/E` in the rotated frame, RHS uses `U log(Σ) Uᵀ` of `F_e`; damping enters as `α = 1/(1 + damping/dt)` — source: `implicit_mpm_solver_kernels.py:20-27, 507-576`. Default `young_modulus = 1e15` (effectively rigid-plastic: "fully inelastic limit"), `poisson 0.3`, `friction 0.5`, `yield_pressure 1e15`, `yield_stress 0`, `tensile_yield_ratio 0`, `hardening 0`, `hardening_rate 1`, `softening_rate 1`, `dilatancy 0`, `viscosity 0` — source: `register_custom_attributes`, `solver_implicit_mpm.py:1190-1390`.
- Hardening (yield scales, not stiffness): `h = sinh(−hardening · log(clamp(J_p, 0.1, 1)))` multiplies yield_pressure and yield_stress (`hardening_law`, :209-217); `J_p ← J_p · clamp(exp(tr(Δε_p) · rate), 0.01, 10)` with `hardening_rate` for compaction and `softening_rate` for dilation (:395-401).
- `F_e` update: `F_e ← F_e + (Δε_e + ½dt(∇v − ∇vᵀ)) F_e`, discarded if a singular value leaves [1e-6, 1e6]; if compliance ≤ 1e-12 (rigid) `F_e = I` (:410-441). Stress is projected back onto the yield surface at the particle (`project_stress`).

Discretisation choices (source: `solver_implicit_mpm.py:851-926, 2421-2560`)
- `grid_type`: `"sparse"` (default) = `fem.Nanogrid` over a NanoVDB `wp.Volume` built from particle voxels (`allocate_by_voxels`), optionally rebuildable in place with leaf/lower/upper node capacities; `"dense"`/`"fixed"` = `fem.Grid3D`. Default `voxel_size = 0.1` m.
- `velocity_basis`: `"Q1"` (default, trilinear), `"B2"`, `"B3"` (B-spline order 2/3 via `fem.ElementBasis.BSPLINE`). `strain_basis`: `"P0"` (default, piecewise constant per cell), `"P1d"`, `"Q1"`, `"Q1d"`, or particle-based `"pic"/"picN"`. `collider_basis`: `"S2"` (default, quadratic serendipity), `"Q1"`, or `"pic*"`.
- `transfer_scheme`: `"apic"` (default) or `"pic"`; `integration_scheme`: `"pic"` (default) or `"gimp"` (shape-function support widened by particle extent).
- `critical_fraction` (default 0): packing fraction below which the yield surface collapses (free-flowing dilute regime); `air_drag` (default 1.0) adds `drag·dt` to nodal mass.
- `separate_worlds` (experimental) isolates grids per world for multi-env RL; outer graph capture "requires CUDA, an enabled memory pool, conditional graph support".

Colliders and rigid coupling
- Colliders are triangle `wp.Mesh`es (from shapes flagged `COLLIDE_PARTICLES`, or user meshes) with per-mesh margin, friction, adhesion (Pa), projection threshold; body-attached, kinematic, or deformable (mesh vertices = particles) — source: `setup_collider`, `solver_implicit_mpm.py:1523-1590`; `Collider` struct `rasterized_collisions.py:44-95`. Collider velocity is `"forward"` (current body_qd) or `"backward"` (finite difference of previous pose).
- Two-way coupling is built in at the impulse level: for finite-mass bodies the solve includes the body's Delassus operator `J M⁻¹ Jᵀ` with mass splitting across overlapping nodes (`compute_collider_inv_mass`, `contact_solver_kernels.py`), so sand-on-body reaction is implicit within the MPM step; the resulting nodal impulses are exposed via `collect_collider_impulses()` and must be applied to the rigid solver by the user (example converts impulse/dt into body wrench at the COM and applies it over the next frame's rigid substeps, subtracting the previous frame's contribution) — source: `upstream/newton/newton/examples/mpm/example_mpm_twoway_coupling.py` (MPM at `frame_dt`, MuJoCo at 4 substeps, voxel 0.05, fixed grid, 50 iterations, P0 strain).
- `example_mpm_anymal.py` is one-way: robot bodies passed with `body_mass = zeros` (kinematic colliders), `transfer_scheme="pic"`, voxel 0.03, `collider_velocity_mode="backward"`, MPM stepped once per 4 MuJoCo substeps.
- Generic multi-solver coupling: `SolverImplicitMPM` implements `CouplingInterface` (`coupling_harvest_proxy_wrenches`, `coupling_rewind_proxy_body`, particle variants; :1937-2175); `SolverCoupledProxy` (lagged one pass, optional Aitken relaxation) is used in `examples/multiphysics/example_{mujoco,xpbd,vbd}_mpm_coupled_solver.py`.
- Newton changelog: rebuildable graph-capturable sparse grids, isolated multi-world MPM, `BodyFlags.KINEMATIC` bodies as zero-mass colliders, USD import of MPM materials (`NewtonMPMMaterialAPI`) — source: `upstream/newton/CHANGELOG.md` lines ~188-250.

Warp features ImplicitMPM depends on (source: imports and calls in `solver_implicit_mpm.py`, `solve_rheology.py`)
- `warp.fem` (PicQuadrature, Nanogrid, Grid3D, polynomial/B-spline/serendipity bases, integrate/interpolate, space partitions), `warp.sparse` BSR matrices (`bsr_zeros`, block types mat13/mat31/mat66, bsr_mm), NanoVDB `wp.Volume` allocation by voxel/rebuild status flags, `wp.svd3`, `wp.eig3`, tile reductions (`ArraySquaredNorm` "tiled reductions"; fem dispatch assembly uses `wp.tile_atomic_add`), radix sort (`compress_node_indices`), CUDA graphs with conditional nodes for the iteration loop (optional; `use_graph`).

Determinism of Newton's transfers (source: `warp/_src/fem/integrate.py:730-791`, `field/virtual.py:684+`, `fem/utils.py:109`, in the Warp fork)
- `fem.integrate` linear forms over a `PicQuadrature` are node-centric gathers: each thread owns a node, loops over its adjacent cells and the particles binned to them, and sums — no float atomics in P2G. Particles are binned with a radix sort (stable LSD sort), so the summation order is fixed by particle index within each cell. "dispatch" assembly evaluates at particles then gathers per node with a tile reduction.
- G2P writes per particle via `wp.atomic_add(pos/vel/vel_grad, p, gimp_weight * ...)`; with `integration_scheme="pic"` each particle has exactly one sample so this is a single add (deterministic); with `"gimp"` several cells add to one particle in unspecified order (order-dependent in float32).

### Inferences
- The Isaac/Newton MPM reference is fundamentally different from Genesis/Taichi MLS-MPM: implicit, large-dt (examples step MPM once per frame at 1/60–1/100 s), rigid-plastic by default (E=1e15), Q1+P0 discretisation, and an iterative nonsmooth solve whose result depends on iteration count/tolerance/colouring order. Trajectory-level parity therefore requires reproducing the same function spaces, colouring, warm-start mode, iteration cap and convergence check — essentially porting the algorithm, not re-deriving it.
- Because P2G is a gather and GS uses graph colouring, Newton's MPM is plausibly run-to-run deterministic on one device for fixed particle order (PIC integration); I did not test this.
- The biggest Metal porting hurdles are `wp.Volume`/NanoVDB-backed `Nanogrid` (avoidable with `grid_type="dense"/"fixed"` → `Grid3D`), `warp.sparse` BSR ops, and CUDA conditional graphs (avoidable: `use_graph` falls back to host loop).

### Gaps
- I did not find a Newton paper or tech report describing the GS-batched / anisotropic local solver extensions beyond the Daviet 2016 citation; the extensions are documented only in code comments.
- Not verified by running: whether `SolverImplicitMPM` runs unmodified on the Warp Metal fork (`metal:0`).

## Q2. Genesis MPM solver: materials, grid, substeps, rigid coupling, boundaries, Quadrants backend and Metal

### Takeaway
Genesis runs a classic explicit MLS-MPM (APIC, quadratic B-spline, dense grid) with six material classes (Elastic, ElastoPlastic, Snow, Sand, Liquid, Muscle) written in Quadrants (Genesis's Taichi fork). MPM-rigid coupling is two-way but explicit (SDF-based grid-velocity projection plus a −mΔv/dt force on the body) and lives only in the legacy coupler; the SAP coupler has no MPM support. Quadrants compiles the MPM solver for Metal (`gs.metal`), but the P2G float-atomic scatter makes it nondeterministic, and several open Quadrants Metal miscompile and addressing issues touch exactly the patterns MPM uses. I found no published Apple-Silicon MPM benchmarks.

### Cited Findings
Source read from `main` on 2026-10-09; base URL `https://raw.githubusercontent.com/Genesis-Embodied-AI/Genesis/main/genesis/` (the repo now redirects to `Genesis-Embodied-AI/genesis-world`).

Solver and transfers — [mpm_solver.py](https://raw.githubusercontent.com/Genesis-Embodied-AI/Genesis/main/genesis/engine/solvers/mpm_solver.py)
- `import quadrants as qd`, class `@qd.data_oriented`: the solver is on Quadrants. A comment still cites taichi_elements for the dt heuristic.
- Quadratic B-spline weights on a 3×3×3 stencil: `base = floor(x·inv_dx − 0.5)`, `fx = x·inv_dx − base`, `w = [0.5(1.5−fx)², 0.75−(fx−1)², 0.5(fx−0.5)²]`.
- Grid: dense, cell struct `{mass, vel_in, vel_out}` with shape `(substeps_local, *grid_res, B)` in SoA layout. `dx = 1/grid_density`, `grid_res = round(density·upper) − round(density·lower) + 1`, grids over 1e9 cells rejected. `use_sparse_grid` and `leaf_block_size` (8) are deprecated no-ops that only warn. On the forward-only path a dirty list of touched cells is zeroed after G2P; with `requires_grad` the whole grid is reset.
- Deformation update: `F_tmp = (I + dt·C)·F`, then `qd.svd(F_tmp)` (skipped for non-viscous Liquid and neo-Hookean Elastic). Each material returns `(F_new, S_new, Jp_new)` and a Kirchhoff stress τ = P·Fᵀ.
- P2G: `affine = −dt·V_p·4·inv_dx²·τ + m_p·C_p`; `grid.vel_in += w·(m_p v_p + affine·dpos)` with `dpos = (offset − fx)·dx`; `qd.atomic_add(grid.mass, w·m_p)`. `V_p = particle_size³ × 1e3` (`_particle_volume_scale = 1e3` "to avoid numerical instability", divided back out when coupling); `m_p = V_p·ρ`. Non-free particles zero `vel_in` on their stencil, so they act as boundary conditions.
- Grid op (`legacy_coupler.mpm_grid_op`) for cells with mass > EPS: `v = vel_in/mass + dt·g` (+ force fields), then tool, rigid, SPH and PBD coupling, then `vel_out = boundary.impose_pos_vel(v)`.
- G2P: `v_p = Σ w v_i`, `C_p = Σ 4·inv_dx·w·v_i ⊗ dpos` (dpos in grid units), `x += dt·v_p`, then the cube boundary; attachments to rigid links (`link_idx`) applied after G2P.
- `MPMOptions` ([options/solvers.py](https://raw.githubusercontent.com/Genesis-Embodied-AI/Genesis/main/genesis/options/solvers.py)): `grid_density = 64`, `lower_bound = (−1,−1,0)`, `upper_bound = (1,1,1)`, `particle_size = 0.01·64/grid_density`, `enable_CPIC = False`. Simulation defaults `dt = 1e-2`, `substeps = 1`, gravity (0,0,−9.81). Warning if `substep_dt > 2e-2·dx` (3.1e-4 s at density 64).

Materials — [materials/MPM/](https://github.com/Genesis-Embodied-AI/Genesis/tree/main/genesis/engine/materials/MPM)
- Base: E = 1e6, ν = 0.2, ρ = 1000; μ = E/(2(1+ν)), λ = Eν/((1+ν)(1−2ν)); default stress fixed-corotated `τ = 2μ(F − UVᵀ)Fᵀ + λJ(J−1)I`. The particle sampler defaults to `pbs` on Linux x86-64 and `random` elsewhere, including Mac.
- Elastic: E = 3e5, `model ∈ {"corotation", "neohooken"}` (default corotation); neo-Hookean `τ = μ F Fᵀ + (λ ln J − μ) I`; no StVK; no plasticity.
- ElastoPlastic: E = 1e6, `use_von_mises = True`, `von_mises_yield_stress = 1e4`, `yield_lower = 2.5e-2`, `yield_higher = 4.5e-3`. Von Mises in Hencky space: `S = max(S, 0.05)`, `ε = log S`, `ε̂ = ε − tr(ε)/3`, `Δγ = ‖ε̂‖ − σ_y/(2μ)`; if Δγ > 0, `ε −= (Δγ/‖ε̂‖) ε̂`, `F = U exp(ε) Vᵀ`. Without von Mises: clamp singular values to `[1 − 2.5e-2, 1 + 4.5e-3]`. Stress: corotated on `F_new`.
- Snow (subclass of ElastoPlastic; von Mises forbidden): Stomakhin 2013 clamp, `Jp *= S/S_clamped` (per axis product), hardening `h = exp(10(1 − Jp))` on μ and λ (ξ = 10 hard-coded).
- Sand: `friction_angle = 45°`, default Jp = 0. Klár 2016 Drucker-Prager: `α = √(2/3)·2 sinφ/(3 − sinφ)`; `ε = log(max(|S|, 1e-4))`; `tr = Σε + Jp` (Jp used as volume-correction term). If `tr ≥ 0`: `Jp = tr`, `S = I` (tension → stress-free). Else `Jp = 0`, `Δγ = ‖ε̂‖ + (3λ + 2μ)/(2μ)·tr·α`, `S = exp(ε − max(0, Δγ)/‖ε̂‖·ε̂)`. Stress is Hencky St.Venant–Kirchhoff: `τ = U diag(2μ ln S/S + λ Σ ln S/S) Vᵀ F_newᵀ`, evaluated with the pre-projection S.
- Liquid: `viscous = False` sets μ = 0; `F_new = J^{1/3} I`; `τ = 2μ(F_tmp − UVᵀ)F_tmpᵀ + λJ(J−1)I`. The equation of state is just λJ(J−1) with λ from E = 1e6, ν = 0.2; there is no separate viscosity parameter.
- Muscle (subclass of Elastic; neo-Hookean, E = 1e6, `n_groups = 1`): base stress plus `E·actu·F_tmp (m⊗m) F_tmpᵀ`, per-particle `actu`, fiber `m` default (0,0,1).

Boundaries and coupling
- Domain walls ([boundaries.py](https://raw.githubusercontent.com/Genesis-Embodied-AI/Genesis/main/genesis/engine/boundaries/boundaries.py), `CubeBoundary`, restitution 0): inset by 3·dx; per axis, if a node/particle is at or beyond a wall and moving outward, that component is multiplied by −restitution (→ 0) and position clamped. Free-slip ("separate") walls; no sticky option. Applied to grid `vel_out` and again to particles in G2P.
- Rigid coupling ([legacy_coupler.py](https://raw.githubusercontent.com/Genesis-Embodied-AI/Genesis/main/genesis/engine/couplers/legacy_coupler.py)), per grid node when `rigid_mpm = True`: for each geom with `needs_coup`, signed distance via `sdf.sdf_func_world`; `influence = min(exp(−sd/coup_softness), 1)`, active only when > 0.1; normal from SDF gradient. In `_func_collide_in_rigid_geom` with `rv = v − v_rigid(x)` and only if `rv·n < 0`: `rv_t ← rv_t/|rv_t| · max(0, |rv_t| + (rv·n)·coup_friction)`, `rv_n ← −n (rv·n)·coup_restitution`, `v = v_rigid + influence·rv_new + (1 − influence)·rv`. The body receives `F = −m_cell Δv/dt` at the node position via `rigid_solver._func_apply_coupling_force` → two-way, explicit, no implicit solve.
- Rigid defaults ([materials/rigid.py](https://raw.githubusercontent.com/Genesis-Embodied-AI/Genesis/main/genesis/engine/materials/rigid.py)): `coup_friction = 0.1`, `coup_softness = 0.002`, `coup_restitution = 0`, `needs_coup = True`, `sdf_cell_size = 0.005`.
- CPIC (`enable_CPIC`, thin objects, from MLS-MPM paper): P2G flags stencil cells on the far side of a geom (`cpic_flag`) and skips them; in G2P the particle velocity is resolved directly against the rigid body. Not supported with `requires_grad`.
- MPM also couples to SPH, PBD and FEM through the same per-node velocity averaging and Δmv exchange.
- [sap_coupler.py](https://raw.githubusercontent.com/Genesis-Embodied-AI/Genesis/main/genesis/engine/couplers/sap_coupler.py) (4007 lines) contains no occurrence of "mpm": SAP does not support MPM.

Backend, Metal, differentiability
- Differentiable MPM: particle fields `needs_grad=True`, stored for `substeps_local + 1` frames, with `p2g.grad`, `svd_grad`, `compute_F_tmp.grad`, `mpm_grid_op.grad`; SVD always computed under `requires_grad`; no CPIC with grad — source: mpm_solver.py above.
- Quadrants compiles the rigid, MPM, SPH, PBD and FEM solvers for Metal; no float64 on Metal; some compiler optimisations forced off on macOS (NaNs); Genesis v1.4.2 runs on `gs.metal` with torch on MPS on this machine — source: `/Users/aditya/robosim/docs/research/competitors_2026-09-25.md:42,128-143` (local research note, rigid-body benchmarks only, no MPM measurement).
- Open Quadrants Metal issues relevant to MPM: [quadrants#925](https://github.com/Genesis-Embodied-AI/quadrants/issues/925) (fence implied by an atomic inside divergent control flow lowered to `threadgroup_barrier` — MPM P2G has atomics inside `if active` / CPIC / dirty-flag branches); [quadrants#835](https://github.com/Genesis-Embodied-AI/quadrants/issues/835) (run-time index into a local vector reads 0.0 in a large kernel; MPM's stencil indexes are static-unrolled, so probably not hit); [quadrants#963](https://github.com/Genesis-Embodied-AI/quadrants/issues/963) (fields above 2/4 GiB mis-addressed on Metal from 32-bit byte offsets — relevant because the grid is dense × substeps_local × B); [quadrants#802](https://github.com/Genesis-Embodied-AI/quadrants/issues/802) (wrong reverse-mode gradients on MoltenVK). Genesis MPM issue [genesis-world#3467](https://github.com/Genesis-Embodied-AI/genesis-world/issues/3467) (partial reset overwrites non-rigid envs).

Determinism
- P2G scatters with float atomics (`vel_in +=` inside a parallel loop, made atomic by Quadrants; explicit `qd.atomic_add` on mass). Grid sums therefore depend on thread scheduling; Genesis MPM is not bitwise deterministic on GPU — source: mpm_solver.py.

### Inferences
- Genesis's defaults are not stable together (dt 1e-2 with 1 substep vs. its own 3.1e-4 warning threshold); scenes must set substeps or dt.
- Because Genesis is explicit MLS-MPM with explicit coupling, it is the easier algorithm to port to Metal but it is not the Isaac/Newton reference; comparisons between a Genesis-style solver and Newton ImplicitMPM can only be statistical (pile angle, flow profile, penetration depth), not trajectory-level.
- The Sand model evaluating stress on the pre-projection S appears deliberate (inherited from taichi_elements).

### Gaps
- No Apple-Silicon MPM performance numbers and no Mac-specific MPM bug reports were found.
- Not confirmed how Quadrants lowers float atomic add on Metal (native `atomic<float>` in MSL 3.0 vs CAS loop).

## Q3. Taichi mpm88 / mpm99 / mpm128 / mpm3d and the papers behind them (MLS-MPM, APIC, snow, Drucker-Prager sand, Daviet 2016)

### Takeaway
The Taichi examples are the canonical explicit MLS-MPM: quadratic B-spline weights on a 3^d stencil, APIC affine matrix `C_p` used as the velocity gradient, one fused P2G term `m_p C_p − dt V_p (4/Δx²) τ_p`, separate (slip) walls 3 cells deep, and fixed-corotated stress with Stomakhin-style hardening. Genesis is a direct descendant of this formulation. The 2016 Daviet paper (Newton's citation) is a different family: rigid-plastic, nonsmooth Drucker-Prager as a constraint, solved implicitly as a contact-like cone-complementarity problem; its 2026 successor "Mixed Material Point Methods" is described by NVIDIA as integrated in Newton.

### Cited Findings
Taichi examples (all fetched from `raw.githubusercontent.com/taichi-dev/taichi/master/python/taichi/examples/simulation/`: [mpm88.py](https://raw.githubusercontent.com/taichi-dev/taichi/master/python/taichi/examples/simulation/mpm88.py), [mpm99.py](https://raw.githubusercontent.com/taichi-dev/taichi/master/python/taichi/examples/simulation/mpm99.py), [mpm128.py](https://raw.githubusercontent.com/taichi-dev/taichi/master/python/taichi/examples/simulation/mpm128.py), [mpm3d.py](https://raw.githubusercontent.com/taichi-dev/taichi/master/python/taichi/examples/simulation/mpm3d.py); 92/133/159/122 lines)
- Weights: `base = int(x/dx − 0.5)`, `fx = x/dx − base`, `w = [0.5(1.5−fx)², 0.75−(fx−1)², 0.5(fx−0.5)²]`, weight = per-axis product.
- P2G: `affine = stress + p_mass·C[p]`; `grid_v[base+off] += weight·(p_mass·v[p] + affine @ dpos)`, `dpos = (off − fx)·dx`; `grid_m[base+off] += weight·p_mass`. In math: `m_i = Σ w_ip m_p`, `(mv)_i = Σ w_ip [m_p v_p + (m_p C_p − dt V_p⁰ (4/Δx²) τ_p)(x_i − x_p)]`.
- mpm88/mpm3d stress: `stress = −dt·4·E·p_vol·(J[p]−1)/dx²·I` (pure-pressure weakly compressible fluid, no ν); `J *= 1 + dt·tr(C)` in G2P.
- mpm99/mpm128: `F = (I + dt C) F` at start of P2G; SVD `U, sig, V`; fixed-corotated Kirchhoff `τ = 2μ(F − UVᵀ)Fᵀ + λJ(J−1)I`; scaled `stress = (−dt·p_vol·4·inv_dx²)·τ`.
- Materials (mpm99/128): hardening `h = exp(10(1 − Jp))` (mpm128 clamps to [0.1, 5]); jelly `h = 0.3`; `μ, λ = μ0 h, λ0 h`; fluid `μ = 0` and `F = I·sqrt(J)` (2D); snow clamps singular values to `[1 − 2.5e-2, 1 + 4.5e-3]` (note: 4.5e-3, not Stomakhin's θs = 7.5e-3), `Jp *= sig/new_sig`, `F = U Σ Vᵀ`. mpm99 clamps sig ≥ 1e-6 first; mpm128 does not.
- Grid update: `v = mv/m` for `m > 0`, then gravity (mpm88/mpm3d `−dt·9.8`; mpm99 `−dt·50`; mpm128 `dt·gravity·30`, plus a mouse attractor).
- Boundary: "separate" slip — zero the velocity component pointing into the wall when within `bound = 3` cells (`if i < bound and v.x < 0: v.x = 0`, `if i > n_grid − bound and v.x > 0: v.x = 0`); asymmetric (low side clamps cells 0–2, high side n−2, n−1). No sticky BC in any example.
- G2P: `new_v = Σ w g_v`, `new_C = 4·inv_dx·Σ w g_v ⊗ (off − fx)` (≡ `4/Δx² Σ w v_i (x_i − x_p)ᵀ`), `x += dt·v`.
- Defaults: mpm88 n_grid 128, dt 2e-4, E 400, 8192 particles, p_vol = (dx/2)², ρ = 1, 50 substeps/frame. mpm99/mpm128 n_grid 128·q, dt 1e-4/q, E 1e3 / 5e3, ν 0.2, 9000·q² particles, substeps `int(2e-3 // dt)`, three blocks (fluid, jelly, snow). mpm3d n_grid 32, dt 4e-4, E 400, 8192 particles (keeps `p_vol = (dx/2)²` even in 3D).

Papers (DOIs below resolve; the formulas here were recalled by the research agent from the papers and were NOT re-checked against the PDFs in this session — treat as claims)
- MLS-MPM — Hu, Fang, Ge, Qu, Zhu, Pradhana, Jiang, ACM TOG 37(4):150, SIGGRAPH 2018, [DOI 10.1145/3197517.3201293](https://doi.org/10.1145/3197517.3201293): APIC `C_p` doubles as the velocity gradient; with quadratic B-splines `D_p = (Δx²/4) I` so `D_p⁻¹ = 4/Δx²` (cubic `3/Δx²`); nodal force `f_i = −Σ_p V_p⁰ M_p⁻¹ (∂Ψ/∂F) F_pᵀ w_ip (x_i − x_p)`, giving the fused P2G term. CPIC: coloured distance field and side tags so transfers happen only between compatible node/particle pairs on the same side of thin rigid boundaries (displacement discontinuity, cutting); incompatible nodes use the particle velocity projected against the rigid surface and the impulse goes back to the body (two-way coupling).
- APIC — Jiang, Schroeder, Selle, Teran, Stomakhin, ACM TOG 34(4):51, 2015, [DOI 10.1145/2766996](https://doi.org/10.1145/2766996): `B_p = Σ_i w_ip v_i (x_i − x_p)ᵀ`, `C_p = B_p D_p⁻¹`; P2G `(mv)_i = Σ w_ip m_p (v_p + C_p (x_i − x_p))`; conserves angular momentum.
- Snow — Stomakhin, Schroeder, Chai, Teran, Selle, ACM TOG 32(4):102, 2013, [DOI 10.1145/2461912.2461948](https://doi.org/10.1145/2461912.2461948): `Ψ = μ(F_P)‖F_E − R_E‖² + λ(F_P)/2 (J_E − 1)²`, `μ = μ0 e^{ξ(1−J_P)}` (same for λ), ξ = 10, θc = 2.5e-2, θs = 7.5e-3, E0 = 1.4e5, ν = 0.2; Σ_E clamped to [1−θc, 1+θs], excess pushed into F_P; semi-implicit grid solve; PIC/FLIP blend 0.95.
- Drucker-Prager sand — Klár, Gast, Pradhana, Fu, Schroeder, Jiang, Teran, ACM TOG 35(4):103, 2016, [DOI 10.1145/2897824.2925906](https://doi.org/10.1145/2897824.2925906): St.Venant–Kirchhoff in Hencky strain `Ψ = μ tr((ln Σ)²) + (λ/2)(tr ln Σ)²`; with `ε = ln Σ`, `ε̂ = ε − (tr ε/d) I`, `δγ = ‖ε̂‖ + ((dλ + 2μ)/(2μ)) tr(ε) α`; if `tr ε > 0` → `Σ = I`, `δq = ‖ε‖`; else if `δγ ≤ 0` no change; else `H = ε − δγ ε̂/‖ε̂‖`, `Σ = exp(H)`, `δq = δγ`; `α = √(2/3)·2 sin φ_F/(3 − sin φ_F)`; hardening `φ_F = h0 + (h1 q − h3) e^{−h2 q}` (typical h0 35°, h1 9°, h2 0.2, h3 10°).
- Daviet & Bertails-Descoubes 2016 — [HAL hal-01310189](https://hal.archives-ouvertes.fr/hal-01310189), [project page](https://elan.inrialpes.fr/people/bertails/Papiers/mpmGranular.html): continuum granular MPM that "enforces the exact nonsmooth Drucker-Prager yield criterion with a varying volume fraction"; semi-implicit stepping keeps the normal/tangential stress coupling; the discrete problem resembles multibody frictional contact so existing nonsmooth solvers apply; validated on silo discharge and column collapse; extended to two-way rigid coupling and anisotropic materials (per search-result summary of the HAL/project pages). Research-agent recollection (unverified): rigid-plastic DP with optional cohesion, De Saxcé bipotential cone complementarity, projected Gauss-Seidel with per-node local solves (so-bogus style).
- Daviet, "Mixed Material Point Methods" (stiff elastoviscoplasticity), ACM TOG / SIGGRAPH 2026 — [NVIDIA project page](https://research.nvidia.com/labs/prl/mixed_mpm/index.html): "a family of mixed Material Point Methods well suited to CFL-rate simulation" extending the 2016 mixed discretisation "to finite-strain viscoelasticity and more general flow rules"; "Our implicit integration scheme yields a well-posed, symmetric optimization problem with compact stencils"; says trilinear velocities are often competitive among "various velocity–stress discretization pairs"; "Integrated as a first-party module in the Newton physics engine"; Code link points to github.com/newton-physics/newton.
- GPU MPM — Gao, Wang, Wu, Fu, Jiang, Sifakis, "GPU Optimization of Material Point Methods", ACM TOG 37(6):254, 2018, [DOI 10.1145/3272127.3275044](https://doi.org/10.1145/3272127.3275044) (claim, from memory): radix-sort particles by cell key into a SPGrid-like sparse grid; warp-level segmented reduction (shuffles) before atomics in P2G; kernel fusion. Adaptive GIMP is a different paper (Gao, Tampubolon, Jiang, Sifakis, ACM TOG 36(6):223, 2017).

### Inferences
- Newton's `velocity_basis` / `strain_basis` options (Q1/B2/B3 × P0/P1d/Q1/Q1d/pic) are exactly the "velocity–stress discretization pairs" of the 2026 Mixed MPM paper, and the hardening/softening/dilatancy/viscosity/Hencky elasticity are its "finite-strain viscoelasticity and more general flow rules". So the 2026 paper, not only the 2016 one, is the spec for the Newton reference.
- Taichi/Genesis-style explicit MLS-MPM needs dt ~1e-4 s at Δx ~1 cm (CFL plus elastic wave speed), i.e. tens of substeps per 1/60 s frame; Newton's implicit solver steps at frame rate. That changes the cost model on Metal: explicit = many cheap atomic-heavy passes; implicit = fewer, heavier iterative passes.

### Gaps
- Paper formulas for MLS-MPM, APIC, snow, sand, GPU-MPM were not re-verified from PDFs in this session (ACM blocked scripted fetches; arXiv had no copies). The Mixed MPM 2026 paper text itself was not read, only its project page.
- No "mpm128" variant with Drucker-Prager sand exists in Taichi core examples; sand in the Taichi ecosystem lives in taichi_elements (not read here).

## Q4. NVIDIA Warp MPM examples, the warp.fem features they need, and what the Metal fork supports

### Takeaway
Upstream Warp has no `example_mpm_*`; its MPM-like examples are `fem/example_apic_fluid.py` (+ multi-env) and the real MPM lives in Newton's `SolverImplicitMPM`. The Metal fork (`metalsim`) supports nearly all needed features — NanoVDB `wp.Volume` (host-built), `warp.sparse` BSR (host path for topology), float32 atomics, tile ops (forward only, 32 KB threadgroup memory) — but not float64, and `warp.fem.integrate` accumulates in float64 by default. Verified here: unmodified `SolverImplicitMPM` fails on `metal:0` for that reason; with `fem.integrate` patched to float32 accumulation it runs on Metal with both dense and sparse grids, matches the CPU to ~1e-8, and is bitwise repeatable run to run.

### Cited Findings
- Upstream Warp MPM/APIC examples (GitHub tree API on `NVIDIA/warp` main): only `warp/examples/fem/example_apic_fluid.py`, `example_apic_fluid_multi_env.py`, `warp/examples/cpp/02_apic_visualization`, `03_apic_visualization_cpu`; no `example_mpm*` — [NVIDIA/warp examples/fem](https://github.com/NVIDIA/warp/tree/main/warp/examples/fem).

- Metal fork capability table (source: `/Users/aditya/robosim/upstream/warp-innate/docs/user_guide/metal.rst:66-100`, branch `metalsim` `c200d46b`, overlay on warp-lang 1.17/1.18.0.dev20260917):

### Inferences
- Porting Newton's reference to Metal looks like a patch-level job in the Warp fork (default `accumulate_dtype` to float32 on Metal, or have Newton pass it) rather than a reimplementation; the remaining risks are performance (host-side NanoVDB rebuilds and BSR topology each step; `block_dim = 1` paths on non-CUDA; no conditional graphs, so the iteration loop is host-driven with convergence checks) and float32 vs float64 accumulation differences against a CUDA reference that accumulates in float64.
- Float32 accumulation changes summation results relative to CUDA Newton (float64 accumulate), so even a faithful port will not be bitwise-equal to Isaac/Newton on CUDA; agreement should be expected at float32 tolerance, which an iterative nonsmooth solver may amplify over long rollouts.

### Gaps
- Only a tiny free-fall-then-settle scene was run; colliders (meshes), two-way coupling, B2/B3 bases, GIMP, multi-world and performance at realistic particle counts on Metal were not tested.
- Not checked whether the fork's tile-reduction kernels in `solve_rheology.py` pass with the 32 KB threadgroup limit at larger sizes.

## Q5. Determinism / reproducibility: atomics in P2G and how to compare against references

### Takeaway
Scatter-style P2G with float atomics (Taichi, Genesis) is order-dependent and not bitwise reproducible on GPUs; Newton's warp.fem P2G is a sorted gather (no atomics), and in our Metal run it was bitwise repeatable. Against a CUDA Newton reference, trajectory-level equality is unattainable (float64 vs float32 accumulation, different hardware, iterative solver), so validation should be statistical/aggregate, with short-horizon trajectory checks only for small scenes.

### Cited Findings
- Genesis P2G uses float atomics (`vel_in +=` in a parallel loop, `qd.atomic_add(grid.mass, …)`), so grid sums depend on thread order — [mpm_solver.py](https://raw.githubusercontent.com/Genesis-Embodied-AI/Genesis/main/genesis/engine/solvers/mpm_solver.py). Taichi examples likewise use `+=` on grid fields inside parallel loops (atomic in Taichi) — [mpm99.py](https://raw.githubusercontent.com/taichi-dev/taichi/master/python/taichi/examples/simulation/mpm99.py).
- warp.fem linear forms are node-centric gathers over a stable radix sort of particles by cell; no float atomics in P2G — source: `warp-innate/warp/_src/fem/integrate.py:730-791`, `field/virtual.py:684+`, `fem/utils.py:109`. Newton G2P uses per-particle `wp.atomic_add` that is a single add per particle under `integration_scheme="pic"` but multiple, order-dependent adds under `"gimp"` — source: `implicit_mpm_solver_kernels.py:332-360, 422-424`.
- Upstream Warp 1.15 added `wp.config.deterministic` (RUN_TO_RUN / GPU_TO_GPU: per-thread records, stable radix sort, fixed-order per-key reduction) — source: `warp-innate/CHANGELOG.md:331`, `docs/user_guide/execution_and_performance/deterministic_execution.rst:127-160`; the Metal fork does not support it (`metal.rst:99`).
- Measured: Newton ImplicitMPM on `metal:0` (float32-accumulate patch) produced identical `particle_q` hashes across two runs for dense and sparse grids (Q4 experiment).

### Inferences
- Options for a deterministic Metal-native explicit MLS-MPM: (1) sort particles by (cell, id) then gather per node over the 3^d neighbouring cells in fixed order (no atomics; what warp.fem does); (2) sort + threadgroup segmented reduction (Gao 2018) — faster, but still nondeterministic if the final merge uses float atomics; (3) fixed-point int atomics (integer add is associative; Metal has native 32-bit, the fork emulates exact 64-bit add) trading range for resolution; (4) per-threadgroup tiles merged in fixed order.
- Comparison protocol against Isaac/Newton: use metrics robust to chaos — angle of repose / pile profile, column-collapse runout distance vs time, silo discharge rate, penetration depth and drag force on a robot foot/tool, mass and momentum conservation, energy dissipation — averaged over seeds/particle samplings; reserve trajectory-level (per-particle) checks for a few steps of small scenes, with tolerances at float32 level, and fix identical particle ordering, function spaces, solver choice, iteration cap/tolerance, warm-start mode and colouring.

### Gaps
- Not measured: whether CUDA Newton ImplicitMPM is itself bitwise run-to-run deterministic (GS colouring and tile reductions suggest yes, but untested); magnitude of float32-vs-float64 accumulation divergence over long rollouts.
- Not confirmed whether Quadrants on Metal lowers float atomic add to native `atomic<float>` or a CAS loop.
