# MPM in the main simulator: status (resume here)

Goal: MPM material (sand, snow, ...) in metalsim's main simulator (`.venv`: BatchSim on MuJoCo Warp 3.14 fork,
Newton 1.7 line), two-way coupled with the robot, N worlds, rendered by `render/particles.py`; parity with the
`.venv-newton152` (Newton 1.5.2 fork, Isaac Lab 3.0-EA) results.

## Decided (2026-10-13, pending the research note)
- Leading option (b): vendor the Newton 1.5.2 fork's `implicit_mpm` package (pin `3fd1f052`, same as
  `scripts/setup_newton152.sh`) into `metalsim/physics/mpm/implicit_mpm/`, generated by `scripts/vendor_mpm152.py`
  (only the 6 package-external relative imports rewritten to `newton._src...`). It imports and runs against Newton 1.7
  (every newton symbol it uses exists in 1.7: checked). Kernels byte-identical to the fork, so results can be checked
  bitwise against `.venv-newton152`.
- `newton_compat.install` patches the vendored `solve_rheology` too (`rheology_modules()`); `rigid_deterministic=None`
  / `device_args=None` leave global Warp / Newton rigid settings alone (main sim must not change MuJoCo Warp kernels).
- `scenes.py` picks the solver via `metalsim/physics/mpm/solver.py` (`METALSIM_MPM_SOLVER=newton|vendored|auto`).
- Coupling layer (to build): metalsim-side, Isaac's lagged exchange semantics: per BatchSim.step, rigid substeps with
  sand wrench in `d.xfrc_applied` (user part restored after), then MPM step with colliders = per-world Newton 1.7
  collider model mirroring MjModel bodies/geoms (`setup_collider(model=...)`, body_mass = effective/body/kinematic),
  fixed-order impulse harvest -> wrench per (world, body).
